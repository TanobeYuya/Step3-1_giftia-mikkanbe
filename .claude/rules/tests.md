# テストを触るときのルール

- テストが失敗したら、期待値を書き換えて通さない。実装を直すか、止まって報告する。
- 承認済みの評価基準（テスト設計）は、変更の理由・影響・旧基準・新基準を記録して再承認を得るまで変えない。
- テストデータは実データを使わず、ダミー値だけを使う。
- 「今日の日付」や乱数に依存させない。引数で渡すか固定する。
- 判定ロジックの単体テストと、DB や外部 API に触る結合テストを分ける。
