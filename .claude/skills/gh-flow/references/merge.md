# レビュー・マージ・片付け・デプロイ

## レビュー

- 他の人の PR をレビューするときは、diff と正本文書の照合を `spec-reviewer` エージェント（sonnet）に任せる。PR にコメントする前に、結果をユーザーに見せる。
- 自分が作った PR の Approve は、軽微な変更（`git.lightChangePaths` だけ）なら通す。コード等の変更を含む場合は、フックがユーザーに確認を求める。

## マージ

1. `gh pr view <番号> --json reviewDecision,files` で、承認の状態と変更したファイルを確認する。会話で「承認された」と聞いただけで判断しない。
2. コード等の変更を含む PR が未承認なら、マージしてよいかユーザーに確認する（フックも確認を求める）。軽微な変更だけなら、未承認でもマージしてよい。
3. `git.mergeMethod` で指定された方法でマージし、ブランチを削除する。

```bash
gh pr merge <番号> --squash --delete-branch
```

4. ローカルを戻す: `git switch main && git pull`

## デプロイ

デプロイ先のサービスと担当者は、プロジェクトごとに違う。条件は `guards.commandRules` に書く（例: 最新コミットの作者、実行してよいブランチ）。

- 条件がある場合は、実行前に自分でも確認する。満たしていなければ実行せず、満たす方法をユーザーに伝える。作者情報を外すなど、条件を回避する方法は取らない。
- 誰がデプロイするかが project.json や CLAUDE.md から分からないときは、実行せずに質問する。
