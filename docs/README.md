# docs の地図

班の書類の置き場所と、V字モデルのどこに当たるかをまとめた。新しく読む人（AI を含む）は、ここから始める。

## 書類と V字モデル

```text
要求定義書（BRD） ─────────────── 受け入れの確認（試用・要求定義書 6章）
  要件定義書（SRS） ───────────── テスト結果（要件定義書 6.4 の TC）
    仕様・設計書（FS・LLD） ────── テスト結果（仕様・設計書 5章の TC）
      実装（giftia/）
```

| 置き場所 | 中身 | 正本 | 変えるときの承認 |
| --- | --- | --- | --- |
| [要求定義書/](要求定義書/) | 誰の、どんな課題を、何を実現して解くか（BR-xx） | `クラス1_3班_みっかんべー_要求定義書.md` | あかぷさん・みかんさんの両方の Approve |
| [要件定義書/](要件定義書/) | 何を作るか（FR・DR・NFR、テストケース 6.4） | `クラス1_3班_みっかんべー_要件定義書.md` | あかぷさん・みかんさんの両方の Approve |
| [設計書/](設計書/) | どうふるまい、どう作るか（SP・DS・TC）。Phase2 以降も同じファイルに足す | `クラス1_3班_みっかんべー_仕様設計書.md` | 作成者以外の1人の Approve |
| [テスト/](テスト/) | TC ごとの実際の結果と判定 | `テスト結果_Phase1.md` など | 作成者以外の1人の Approve |
| [evidence/](evidence/) | スクリーンショット・ログ（テスト結果から参照する） | — | 作成者以外の1人の Approve |
| [図/](図/) | ER図・構成図（drawio と png） | — | 作成者以外の1人の Approve |
| [mtg/](mtg/) | 議事録・MTG の資料 | — | 作成者以外の1人の Approve |

- 個人ごとの版（`要件定義書_べー.md` など）は、チーム版の元にした記録として残している。正本ではない。
- `dashboard.md`・`dashboard-wording.md`・`public-repo-checklist.md` は、進捗ダッシュボードと公開の手順の文書。

## 番号のつながり

```text
要求（BR）→ 要件（FR・DR・NFR）→ 仕様（SP）→ 設計（DS）→ テスト（TC）→ Issue・PR
```

どの書類も、上の番号を「対応」の欄に書く。上にたどれないものは作らない。

## テストの扱い

テストケース（TC）は実装より先に決めた合格の基準で、実装の PR の中では変えない。詳しくは、仕様・設計書の 0.3 を読む。
