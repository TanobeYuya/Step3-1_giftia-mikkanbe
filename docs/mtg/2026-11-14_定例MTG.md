## 議論の要点

### 1. 要求定義書・要件定義書の見直し

- あかぷさん：他班の定義書へのフィードバックを読み、班の要求・要件と、いま作っているものが合っていないと感じた。結果カードの「母 12件」のタグを見て安心する人（安心型）もいれば、母の発言や暮らしを思い出せないと決められない人（思い出し型）もいる。Dさんは思い出し型で、タグの数字だけでは思い出すきっかけにならない。母に贈った人のレビューを読めば、自分の母の発言を思い出すきっかけになる。
- べー：成功を2段に分けることに賛成。ゴールの設定が足りていなかった。ゴールは「実装で、Dさんの課題が本当に解決したかが分かること」。
- べー：残りは約10日（発表は 11/24（火））。30人の試用は間に合うか分からない。試用の結果を待つ間に開発を止めると、どちらも終わらないおそれがある。規模を小さくし、開発と並行して進めたい。相手を広げる Phase2 は見直し、Dさんの課題の解決を深掘りしたい。
- あかぷさん・みかんさん：賛成。

### 2. Phase2 で何を、どの順に作るか

- べー（A案）：レビュー本文には「毎日使ってくれているようです」のような、使う場面の言葉が残っている。これを抜き出して見せれば、使う場面を想像するきっかけになる。
- あかぷさん（B案）：生成AIとのやり取りを通じて、自分の母との場面を思い出してもらう。Dさんが自分で母の暮らしを思い返して気づいたのなら、他の人のレビューより、本人に焦点を当てた問いかけのほうがよい。
- みかんさん：A案に賛成。
- べー：B案の懸念を挙げた。① セキュリティ：入力が AI 側に送られることへの同意をとる仕組みがない。API キーが漏れると勝手に使われる。② 費用：呼ぶたびに利用料がかかる。決まった質問には決まった答えを返す仕組み（RAG など）やオープンソースの AI で抑える方法がある。③ 一貫性：AI は聞くたびに答えが変わる。
- べー：③の対策として、ベクトル検索（文の意味が近い商品を探す仕組み）を入れれば、同じ言葉には同じ結果を返せる。
- 工数の見込み（生成AIに聞いた目安）：レビュー表示 1〜2日、生成AIとの対話 3〜5日、ベクトル検索 約3日。合計 7〜11日で、発表に対してぎりぎり。
- 順番の決め方：最小の労力で最大の成果を出すため、早く作れて、課題の解決に効きそうな順にした。ベクトル検索は、検索する言葉を思いついていないと使えないため、最後にした。3人とも「レビュー → 生成AI → ベクトル検索」の順で一致した。

### 3. 性能とアンチパターン

- あかぷさん・みかんさん：検索したあと、結果の表示が遅い。
- べー：応答時間の目標を要件にまだ決めていない。課題（アンチパターンになっていないかの確認）もまだなので、合わせて確かめる。

### 4. 自分が実装した部分の説明

- みかんさん：検索画面（page.tsx）で入力した値を状態として覚え、検索ボタンで lib/api.ts の関数が API を呼ぶ。結果は ResultCard.tsx で1件ずつ表示する。
- あかぷさん：FastAPI で受け取った値を確かめ、シーンで絞り、並べる。タグの材料は、表示する商品の ID をまとめて2回で取る（N+1 を避ける）。
- べー：母に贈ったレビューの件数を SQL で数え、product_facts に入れた（祖母・叔母などを除く）。

### 5. デプロイ

- 班の環境へのデプロイはべーが行う。各自で試すときは、班のリポジトリをフォークして自分のリポジトリで行う。
- フォークとクローンの違い：クローンは同じリポジトリを手元に写して、元へ push できる。フォークは別のリポジトリとして丸ごと写すため、元へ直接 push できない。

## MTG のあとに決めたこと（べーとチャットで）

- 試用は3〜6人（1人あたり1〜2人に声をかける）を2回に分ける。1回目は今の Phase1 の画面で1〜2人、2回目はレビュー表示ができてから。結果を待たずに開発を進める。
- 試用で外れたと分かっても、開発は中止しない。思い出すきっかけの見せ方を直して続ける。
- レビュー表示の形：結果カードを押すとモーダルを開き、商品名・価格・説明文と、レビューの一覧を出す。
  - 一覧の順番：母に贈ったレビューを先頭にし、「母に贈った人」の印を付ける。本文のないレビューは出さない
  - レビュー1件ごとのカード：評価点と、原文のままの本文を出す。色はセンチメントで変える（ポジティブは薄い青、ネガティブは薄い赤、ニュートラルとポジネガ混在は薄いグレー）。使う場面を想起させる文はハイライトする
  - センチメントと、使う場面の文は、開発のときに1回だけ判定し、人が確かめてから DB に入れる。画面から LLM は呼ばない
  - レビューが0件なら「まだレビューがありません。」と出す。説明文はどの場合も出す
- 使う場面の選択肢（FR-07）と、贈る相手の拡大は Phase3 へ移す。
- 検索の応答は1秒以内を目標にする。DB への接続を使い回して直す。
