### 3. 仕様・設計書と V字モデル

- 仕様・設計書は、どのプログラムを、どの経路で、どの関数で動かすかを具体的に決める文書。具体的に決まっていれば、AI に任せても意図どおりに作れる。
- V字モデル：要件定義・基本設計・仕様設計・詳細設計の各段階に、対応するテスト（システムテスト・結合テスト・単体テスト）がある。テストの内容は、プログラムを書く前に決めておく。
- 仕様・設計書には、テストケースと、テストが通らないときにコードを直す決まりを書いている。
- あかぷさんが仕様・設計書を確認して承認した。構成図（画面の入力から API、DB の問い合わせを経て、結果カードに返すまでの流れ）は分かりやすいと評価があった。

### 4. Issue を使った GitHub Flow

- Issue はタスクを管理する場所。テンプレート（機能の追加・不具合の報告）に、困っていること、やること、やらないこと、完了の条件を書く。
- 各自が「README に名前と役割を書き足す」Issue を立て、Claude Code に「オープンな Issue を確認して」と頼んで、PR の作成からマージまでを通した。
- PR の本文に `Closes #番号` を書くと、マージしたときに Issue が自動で閉じる。
- PR と Issue は同じ連番を使うため、番号は一致しない。
- Claude Code は `/clear` で会話をリセットできる。
- AI に PR を読ませて、確認やレビューの壁打ちもできる。
