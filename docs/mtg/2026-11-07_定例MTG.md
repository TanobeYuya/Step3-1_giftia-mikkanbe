## 議論の要点

### 1. 課題の捉え方と解決案

- 3人とも、ターゲットは D（家族への誕生日）を選んでいた。
- あかぷさん：手がかりは持っているのに、思い出して選ぶ材料にできていないことが課題。商品ごとに「相手がこれを使う場面を想像できるか」を「ある・ない・分からない」で問いかけ、思い出してもらう案。
- みかんさん：手元に情報はあるが、検索するときに思い出せず、選ぶ材料にできていないことが課題。利用シーンを見せる、質問に答えて絞り込む、覚えている言葉で探す、といった機能が要る。
- べー：使う場面を想像させる手がかりがサイトにないことが課題。商品カードへのタグ付け（母の日・母親向けなど）、意味で探せるベクトル検索、同じ相手に贈った人の声の表示を案に挙げた。
- AI が案を「聞く」「見せる」「自由記述で探す」の3つに分類していた。べーは、3案は対立ではなく、思い出してもらう手段の違いだと整理した。
- みかんさん：自由記述は、そもそも何を探すかを思いつかない人には難しい。視覚的にイメージしやすい「見せる」がよさそう。
- あかぷさん：残りの時間で作れるものと、課題の解決に直結するかで、機能を1〜2個に絞るべき。作ってみてイメージと違えば、作り直す時間を取りたい。
- べー：作り直す余裕は少ないので、購入率や返品率の改善につながるかで選びたい。ユーザーの手数が少なく、絞り込みを進められる機能がよい。

### 2. 使えるデータと、プルダウンの案

- 既存のテーブル（product_scenes）に、母の日・誕生日など「どのイベントで選ばれたか」の情報がある。これでシーンはある程度出せる。
- 「毎日の朝食」のような日常の場面の情報はない。付けるなら、商品説明から生成 AI でシーンを付けるか、レビューから抽出してタグにする方法がある。
- べーの提案：検索画面の「すべてのカテゴリー」のプルダウンを、贈る相手との関係や想定シーンで絞り込めるようにする。何を探せばよいか分からず、とりあえずランキングを見る人への答えにもなる。
- あかぷさん：賛成。ただし今の画面ではプルダウンで絞り込めることに気づきにくいので、見せ方の工夫が要る。分類の切り方は、みかんさんの感覚を生かしたい。
- 「見せる」と「聞く」の中間の案として、プルダウンを最初に作る機能にすることで合意した。

### 3. GitHub の PR とレビュー

- PR は、自分の変更をみんなの共有フォルダ（リポジトリ）に反映する手続き。タイトルに何を変えたか、本文になぜ変えたかを書く。
- Reviewers に設定した人が承認しないと、マージできないように設定できる（PM の確認を必須にする、などのセーフティになる）。レビュアーは2人以上にもできる。
- レビューの手順：Files changed で変更点（赤が削除、緑が追加）を見る → Submit review で Approve を選び、コメントを書いて送る → Merge pull request → Confirm merge。
- みかんさんとあかぷさんが、べーの PR を実際に承認・マージした。
- マージ後は、各自の手元（ローカル）を最新に追いつかせる（pull）必要がある。

### 4. Claude Code の導入と GitHub 操作

- VS Code の拡張機能「Claude Code for VS Code」を入れ、新しいセッションから「GitHub の操作をできるようにして」と頼むと、GitHub CLI（gh）の導入やログインを案内してくれる。権限の確認は基本的に許可してよい。
- リポジトリと連携するときは、GitHub の「Code」ボタンの HTTPS の URL を渡す。
- みかんさんは GitHub へのログインで何度かエラーになったが、エラー画面のスクリーンショットを Claude Code に貼り、指示を1つずつ実行してログインできた。ターミナルへの貼り付けは Ctrl+Shift+V。
- 共同開発用のフォルダは、デスクトップなどに新しく作り、そこにチームのリポジトリをクローンする。以後の共同開発はその中で行う。
- ブランチ：新しい作業を始めるときは必ず新しいブランチを切る。リポジトリのルール（AGENTS.md）に書いてあるので、Claude Code が従ってくれる。
- Claude Code がフォルダの場所を知っているのは、裏でファイル一覧（ls・dir 相当）を調べ、ファイル名から探しているため。
- あかぷさんはクローンと pull ができ、要件定義書の PR を出した（べーがマージ）。みかんさんも自分の要求定義書・要件定義書の PR（#12）を出し、べーがマージ。pull して、あかぷさんの文書が手元に届くことを確かめた。
