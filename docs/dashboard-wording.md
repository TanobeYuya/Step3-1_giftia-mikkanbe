# 進捗ダッシュボードの用語と表記

画面の言葉の意味を、一か所にそろえる。画面の下の「用語の見方」と、同じ内容にする。画面の文言を変えるときは、この文書も直す。

## 状態の言葉

| 対象 | 表記 | 意味 |
| --- | --- | --- |
| Issue | 未完了 | 対応が終わっていない（GitHub の Open） |
| Issue | 完了 | 対応が終わって閉じた（Closed のうち、実施した） |
| Issue | 対象外 | 実施しないと決めて閉じた（GitHub の「Close as not planned」）。完了率の計算から除く |
| PR | 下書き | レビューを依頼する前（GitHub の Draft） |
| PR | マージ前 | まだ取り込まれていない。確認中・修正中を含む（GitHub の Open） |
| PR | マージ済み | 取り込まれた |
| PR | 却下 | 取り込まずに閉じた |
| タスク（WBS） | 未着手・進行中・完了 | `schedule.yml` の status。紐づく Issue が完了していれば、完了 |
| タスク（WBS） | 遅れ | 予定終了日を過ぎても、完了していない |

## 数と日付の言葉

| 表記 | 意味 |
| --- | --- |
| 完了率 | 完了した Issue ÷（全 Issue − 対象外）。マイルストーンごとと、全体で、同じ式 |
| PR 滞留 | 作成から 3 日以上、マージも却下もされていない PR（下書きは除く） |
| データ取得 | このページのデータを GitHub から取得した日時。「あと N 日」や「遅れ」は、この日を基準に数える |
| 組織内のみ | 資料の共有設定が、同じ組織のメンバーだけに開く（ログインが必要） |
| リンクを知る全員が開ける | URL を知っていれば、誰でも開ける |

マイルストーンには、「未着手」「進行中」の札を出さない。GitHub のデータから判断できないため。出すのは、「完了」と「期限超過」だけ。

## 表記のルール

- 状態は名詞で書く。画面に「Open」「Closed」は出さない。
- 色だけで意味を伝えない。意味は、必ず文字でも伝える。
- 件数は「件」、日数は「日」を付ける。
- 「Issue」「PR」は、GitHub の用語として、そのまま使う。
- メンバーの名前は、本名ではなく、ニックネームを使う。
- フォントは BIZ UDゴシックだけを使う。
