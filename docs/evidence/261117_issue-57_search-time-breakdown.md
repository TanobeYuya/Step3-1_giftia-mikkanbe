# 検索1回の時間の内訳（2026-11-17、読み取りの測定）

- 対応：#57（B2）、仕様・設計書 DS-06 段階③・④、10.2「1回の接続にかかる時間」
- 測った日・人：2026-11-17、べー（Claude Code が実行）
- 方法：手元のパソコンから、`giftia/backend/database.py` の `get_connection()` で班の DB（`giftia_t103`）に接続した。main.py の `search()` と同じ SQL を組み立て、SELECT と `EXPLAIN ANALYZE` だけを流した（書き込みはしていない）。各5回の中央値
  - 接続：`get_connection()` を開いて閉じるまで
  - 往復込み：同じ接続で SQL を流し、結果を受け取るまで
  - DB の中：`EXPLAIN ANALYZE` の、いちばん外側の actual time
- API は通していない。手元の数字には、Azure の中にはない時間が入る（SP-21 の合否には使わない）

| 条件 | 件数の SQL（DB の中／往復込み） | 商品の SQL | シーンのタグ | product_facts のタグ | DB の中の合計 |

## 分かったこと

- `recipient=mother&scene=誕生日` の1回は、計算上 約5.4秒。内訳は、接続 1.14秒×4回 ≒ 4.6秒、往復 約0.16秒×4回 ≒ 0.65秒、DB の中 0.17秒
- DB の中の時間は全体の約3%。インデックスで縮むのはこの部分だけ。どの索引を足しても、縮むのは最大で約0.15秒
- そのため、接続と往復の回数を減らす（DS-06 段階①〜④）。インデックスは、段階④のあとに測っても1秒を超えたときに見直す
