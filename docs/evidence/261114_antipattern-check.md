## これから作るもので、避けるアンチパターン

| 機能 | 避けること | どう作るか |
| --- | --- | --- |
| ① レビューのモーダル（FR-06） | 検索のたびに、全カードのレビューを取る（N+1、無駄な通信） | モーダルを開いたときに、その商品の分だけ取る API を1本足す。商品 ID は形（G＋4桁）を確かめる |
| ① ハイライト | `dangerouslySetInnerHTML` で HTML を埋め込む（XSS：レビュー本文に仕込まれたスクリプトが動く） | 文字列を分けて `<mark>` で囲み、React の自動エスケープに任せる |
| ① センチメント | 表示のたびに LLM を呼ぶ（費用、キーの管理、毎回結果が変わる） | 開発のときに文の辞書を作り、人が確かめて DB に入れる |
| ② 生成AIとの対話（FR-08） | API キーを画面側（`NEXT_PUBLIC_`）に置く。入力をログに残す。上限なしで呼ぶ。AI の出力をそのまま信じる | キーはバックエンドの `.env` だけに置く。入力は保存せず、画面で同意をとる。回数と長さに上限を設け、タイムアウトを決める。出力は画面に出す前に形を確かめる |
| ③ ベクトル検索（FR-09） | 検索のたびに、全商品をベクトルに変える | 商品側は事前に変えて保存する。検索のたびに変えるのは検索語だけ |
