## 2. localhost と 127.0.0.1 の比較（TC-22 の手元の値。SP-21 の合否には使わない）

`GET /api/search?recipient=mother&scene=誕生日` を、同じ API（ポート 8001）に 10 回。DB は班の DB（`giftia_t103`）で、SELECT だけを流した。Python の `urllib` で測った。

| 宛先 | 中央値 | 1回目 | 各回（秒） |
| --- | --- | --- | --- |
| `localhost`（1回目の組。起動直後） | 3.29秒 | 5.11秒 | 5.11 3.31 3.31 3.29 3.28 3.32 3.27 3.26 3.27 3.30 |
| `127.0.0.1` | 1.27秒 | 1.31秒 | 1.31 1.26 1.30 1.26 1.28 1.29 1.36 1.26 1.24 1.26 |
| `localhost`（2回目の組） | 3.29秒 | 3.32秒 | 3.32 3.40 3.28 3.25 3.31 3.28 3.28 3.29 3.32 3.28 |

- 差は約 2.0 秒。毎回ほぼ同じ値で、回線のゆれではない
- 理由を確かめた。`localhost` は `::1`（IPv6）と `127.0.0.1`（IPv4）の両方に解決される。`::1` への接続は、約 2.03 秒後に `ConnectionRefusedError` で終わる（uvicorn が IPv4 だけで待ち受けているため）。そのあと IPv4 につながる。`127.0.0.1` への接続は 0.00 秒
- 1 回目の組の最初の 5.11 秒には、プール作成（約 1.5 秒）と、この約 2 秒が重なっている
- 2 秒のずれは API の速さではなく、Windows の名前解決と接続の順序による。デプロイした API（SP-21 の合否）には関係しない

## 判断

- 手元の測定は `127.0.0.1` で行う。DS-06 の測り方の `http://localhost:8000` は、Windows では約 2 秒を足すため、`127.0.0.1` に直す提案を #57 に出す（文書は別の PR）
- 段階③・④に進むかは、DS-06 のとおり、デプロイした API の測定（11/20 の evidence）で判断する。この表の手元の値は、その判断に使わない
